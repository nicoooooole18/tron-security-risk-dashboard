# PRD：JustLend USDT 黑名单风险监控

## 1. 项目名称

JustLend 平台外部风险因素监控：USDT 黑名单命中与 SEV-2 告警

## 2. 背景

在 JustLend 关联地址自清算与 USDT 黑名单风险分析中，已观察到黑名单地址可能通过清算、赎回、抵押品迁移等链上行为，将其在协议中的经济价值迁移至其他地址。

平台需要建立一套轻量、可持续的外部风险因素监控能力，用于每天识别 JustLend 当前用户是否命中 USDT 当前黑名单，并在命中后持续关注其后续清算、赎回、转出、跨地址迁移等行为。

本需求不追求重建 JustLend 与 USDT 黑名单在全部历史时间上的每一刻交集。MVP 聚焦当前风险识别与后续行为追踪。

## 3. 目标

- 业务目标：
  - 每日识别 JustLend 当前用户中是否存在 USDT 当前黑名单地址。
  - 对命中地址建立风险关注池，便于平台工作人员持续跟进。
  - 当命中地址在黑名单之后发生清算或大额抵押品迁移时，触发 SEV-2 告警。

- 用户目标：
  - JustLend 平台工作人员可以在一个监控主页快速判断当前是否存在黑名单风险地址。
  - 点击风险项后，可以查看该地址的风险链路、链上证据和处理状态。

- 成功指标：
  - 每日扫描任务成功率 ≥ 99%。⚠️ 待确认
  - 黑名单命中地址识别延迟 ≤ 24 小时。
  - SEV-2 告警可追溯率 100%，每条告警均包含触发原因和链上证据。

## 4. 用户画像

- 核心用户：
  - JustLend 风控 / 运营工作人员
  - 值班人员
  - 产品与数据分析人员

- 使用场景：
  1. 工作人员每天查看监控主页，确认当前 JustLend 是否存在 USDT 黑名单命中地址。
  2. 发现命中地址后，进入详情页查看该地址的 JustLend 身份、黑名单状态和后续行为。
  3. 当命中地址发生清算或大额抵押品迁移，工作人员收到 SEV-2 告警并进行人工核查。

- 关键痛点：
  - 仅看 Risk Value 无法识别 USDT 黑名单外部风险。
  - 全量历史回溯成本高，且如果不定义时间区间，结论容易失真。
  - 黑名单命中本身不等于法律结论，需要用链上事实和人工核查形成处置闭环。

## 5. 范围

### 本期包含

- 每日扫描 JustLend 当前用户与 USDT 当前黑名单的交集。
- 命中地址进入风险关注池。
- 命中地址后续行为追踪：
  - JustLend 相关清算；
  - 抵押品赎回；
  - 抵押品转出；
  - 抵押品跨地址迁移。
- SEV-2 告警：
  - 黑名单地址在黑名单之后发生 JustLend 相关清算；
  - 黑名单地址在黑名单之后发生单笔或 24 小时累计 ≥ 100,000 USD 的抵押品迁移。
- 两个页面：
  - 风险监控主页；
  - 风险详情页。

### 本期不包含

- 不做全量历史每时每刻的 JustLend 用户快照重建。
- 不做“全量历史 JustLend 用户 ∩ 全量历史 USDT 黑名单”的粗口径交集。
- 不自动限制、冻结或干预链上清算。
- 不自动给出洗钱、制裁、违法等法律定性。
- 不做复杂多页面后台。
- 不做面向普通用户的前台展示。

## 7. 交互要求

### 7.1 顶部导航入口

1. 页面沿用 v2.2.0 监控平台顶部导航结构。
2. 顶部一级导航顺序为：
   - 数据监控；
   - 事件总览；
   - 告警中心；
   - 外部风险识别；
   - 设置与权限。
3. `外部风险识别` 位于 `告警中心` 与 `设置与权限` 之间。
4. 用户 hover 或点击 `外部风险识别` 时，系统展示下拉菜单：
   - 地址黑名单；
   - 币种风险清单。
5. `地址黑名单` 为本期 v2.3.0 内容，默认高亮并进入 USDT 黑名单风险监控页面。
6. `币种风险清单` 为预留入口，本期不展开具体页面。⚠️ 待确认后续版本范围

### 7.2 风险监控主页

1. 用户进入页面。
2. 系统展示顶部风险汇总：
   - 当前黑名单命中地址数；
   - 今日新增命中地址数；
   - 当前待处理 SEV-2 数量；
   - 最近扫描时间；
   - 数据同步状态。
3. 用户在下方查看风险项模块：
   - 黑名单命中地址；
   - 黑名单地址关联清算；
   - 黑名单地址大额抵押品迁移；
   - 数据同步 / 扫描异常。
4. 用户点击具体风险项。
5. 系统进入风险详情页。

### 7.3 风险详情页

1. 系统展示风险地址当前状态。
2. 系统展示该地址在 JustLend 中的身份：
   - jUSDT holder；
   - jUSDD holder；
   - USDT borrower；
   - USDD borrower；
   - ⚠️ 待确认：是否展示其他身份标签。
3. 系统展示黑名单时间线：
   - 当前 `getBlackListStatus(address)` 返回结果；
   - `AddedBlackList` 时间；
   - `RemovedBlackList` 时间，如有。
4. 系统展示黑名单之后的风险行为：
   - 清算；
   - 赎回；
   - 转出；
   - 跨地址迁移。
5. 用户根据证据链进行人工核查，并更新处理状态。

### 7.4 状态流转

系统自动处理链上事实，人工处理风险结论。

| 状态 | 触发方式 | 说明 |
| --- | --- | --- |
| 待核查 | 系统自动创建 | 地址命中黑名单或触发 SEV-2 后生成 |
| 核查中 | 人工操作 | 工作人员开始核查 |
| 已确认风险 | 人工操作 | 工作人员确认需要持续关注或升级 |
| 误报 / 无需处理 | 人工操作 | 工作人员确认无需继续跟进 |
| 已关闭 | 人工操作 | 本轮风险处理完成 |
| 重新打开 | 系统或人工 | 地址出现新的清算、迁移或其他风险行为 |

BR-001: 系统不得自动将告警状态置为“已确认风险”。

BR-002: 系统可以自动创建告警、追加证据、更新黑名单状态、重新打开已关闭风险。

BR-003: 人工关闭风险时必须填写关闭原因。

## 8. 内容要求

### 8.1 每日扫描规则

BR-004: 每日扫描对象为 JustLend 当前用户地址池。

BR-005: JustLend 当前用户地址池包括：
- 持有 `jUSDT` 的地址；
- 持有 `jUSDD` 的地址；
- 借款 `USDT` 的地址；
- 借款 `USDD` 的地址。

BR-006: 当前黑名单状态以 USDT `getBlackListStatus(address)` 返回结果为准。

BR-007: 当 JustLend 当前用户地址调用 `getBlackListStatus(address)` 返回 `true` 时，该地址进入风险关注池。

BR-008: `AddedBlackList`、`RemovedBlackList` 用于补充时序和证据链，不用于单独判断当前风险。

### 8.2 SEV-2 触发规则

BR-009: 地址进入 USDT 黑名单之后，发生 JustLend 相关清算，触发 SEV-2。

BR-010: 地址进入 USDT 黑名单之后，发生单笔 ≥ 100,000 USD 的抵押品迁移，触发 SEV-2。

BR-011: 地址进入 USDT 黑名单之后，24 小时累计抵押品迁移金额 ≥ 100,000 USD，触发 SEV-2。

BR-012: 黑名单之前发生的清算或迁移仅作为背景证据，不单独触发 SEV-2。

BR-013: 清算角色同时记录 `liquidator` 和 `liquidated_user`，但告警中必须明确当前黑名单地址对应的角色。

### 8.3 抵押品迁移规则

BR-014: 抵押品迁移优先统计与 JustLend 抵押品资产相关的赎回、转出、跨地址迁移。

BR-015: 迁移金额同时记录原始资产数量和 USD 估值。

BR-016: 24 小时累计窗口按触发交易时间向前滚动统计。

BR-017: 价格缺失时，该风险项进入“待估值”状态，不直接视为未命中。

### 8.4 UI 文案规格

| 场景 | 中文文案 | 英文文案 |
| --- | --- | --- |
| 当前无命中 | 当前未发现 JustLend 用户命中 USDT 黑名单 | No JustLend user currently matches the USDT blacklist |
| 命中黑名单 | 该地址当前命中 USDT 黑名单，建议关注其后续 JustLend 行为 | This address currently matches the USDT blacklist. Follow up on its JustLend activity |
| SEV-2 清算 | 黑名单地址在进入黑名单后发生 JustLend 相关清算，需人工核查 | A blacklisted address had JustLend-related liquidation activity after being blacklisted. Manual review is required |
| SEV-2 大额迁移 | 黑名单地址在进入黑名单后发生大额抵押品迁移，需人工核查 | A blacklisted address had large collateral movement after being blacklisted. Manual review is required |
| 待估值 | 当前价格或 exchangeRate 缺失，待估值后确认是否达到阈值 | Price or exchangeRate is missing. Threshold evaluation is pending |

## 9. 技术约束

- 平台：JustLend 监控后台（$Monitoring）
- 前端框架：⚠️ 待确认
- API 依赖：
  - JustLend 当前用户地址池；
  - USDT `getBlackListStatus(address)`；
  - USDT `AddedBlackList` / `RemovedBlackList` 事件；
  - JustLend 清算事件；
  - JustLend 抵押品赎回、转出、跨地址迁移事件；
  - jToken exchangeRate；
  - 资产 USD 价格源。
- 埋点要求：
  - `blacklist_monitor_view`
  - `risk_item_click`
  - `risk_detail_view`
  - `alert_status_change`
  - `evidence_tx_click`

### 9.1 数据与估值约束

BR-018: jToken 不得直接按 token 数量判断 USD 阈值。

BR-019: jToken 底层资产数量 = jToken 数量 × exchangeRate。

BR-020: USD 价格取触发区块最近可用价格。⚠️ 待确认：价格源与最大允许延迟。

BR-021: 每条 SEV-2 告警必须保存触发时的估值依据。

### 9.2 告警去重

BR-022: 同一地址同一触发类型在同一 24 小时窗口内的累计迁移应合并为一条告警，并保留明细交易。

BR-023: 建议去重键为 `blacklisted_address + trigger_type + role + window_start + primary_tx_hash`。⚠️ 待确认

## 10. 验收标准

- [ ] 系统可每日扫描 JustLend 当前用户地址池。
- [ ] 系统可对地址调用 USDT `getBlackListStatus(address)` 并识别当前黑名单命中地址。
- [ ] 命中地址可进入风险关注池，并在监控主页展示。
- [ ] 顶部导航在 `告警中心` 与 `设置与权限` 之间展示 `外部风险识别`。
- [ ] `外部风险识别` 下拉菜单包含 `地址黑名单` 和 `币种风险清单`。
- [ ] `地址黑名单` 为当前选中入口，并进入本期 USDT 黑名单风险监控页面。
- [ ] 风险监控主页可展示当前命中数、今日新增命中数、待处理 SEV-2、最近扫描时间。
- [ ] 风险详情页可展示地址、当前黑名单状态、JustLend 身份、黑名单时间线。
- [ ] 地址进入黑名单后发生 JustLend 相关清算时，系统生成 SEV-2。
- [ ] 地址进入黑名单后发生单笔或 24 小时累计 ≥ 100,000 USD 的抵押品迁移时，系统生成 SEV-2。
- [ ] SEV-2 告警可展示交易哈希、区块时间、资产、原始数量、USD 估值、触发原因。
- [ ] 价格或 exchangeRate 缺失时，风险项进入“待估值”状态。
- [ ] 人工可将告警状态流转为核查中、已确认风险、误报 / 无需处理、已关闭。
- [ ] 系统不得自动标记“已确认风险”。
- [ ] 所有人工状态变更保留操作人、时间和备注。
