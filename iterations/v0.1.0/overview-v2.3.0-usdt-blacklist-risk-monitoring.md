## 版本目标

1. 在平台风险看板的外部风险模块中建立第三方冻结风险展示能力。
2. 真实接入 TRON V1 `USDT`、`USDCOLD` 市场，识别核心地址冻结命中、第三方协议状态异常和高风险资金流入。
3. 为 ETH V2 `USDD/USDC`、`WBTC/USDC`、`wstUSDT/USDC`、`wsETH/USDC` 预留看板展示位，待市场上线和地址确认后接入。
4. 不接入 Telegram / 飞书等推送渠道，一期通过看板完成发现、核查、处置、留痕。

## 需求背景

- **用户反馈**：平台工作人员需要更早识别第三方发行方或包装资产协议的冻结能力是否影响 JustLend 市场。
- **风险事件**：Zama cUSDC 事件显示，当争议资金进入共享池合约后，发行方可能按合约地址冻结，导致无关用户被连带影响。
- **产品方向**：将外部冻结风险纳入监控后台，补充单纯 Risk Value 之外的合规、声誉和市场运行可用性观察能力。

## 不做的范围

- 不做全量历史每时每刻 JustLend 用户快照重建。
- 不做全量历史 JustLend 用户与全量历史第三方冻结名单的粗口径交集。
- 不自动冻结、限制或干预链上清算。
- 不自动输出法律定性。
- 不接入 Telegram、飞书、Slack、邮件等推送渠道。
- 不做脱锚、DEX 深度、清算坏账、oracle 偏差、大户集中度等完整市场风险矩阵。

## 当前关注点

- TRON V1 USDT、USDCOLD watched address 清单需要确认。
- USDT 当前冻结状态以 `getBlackListStatus(address)` 为准，历史事件仅用于时序和证据链。
- USDCOLD 是否具备 blacklist / freeze / pause 能力需要确认。
- ETH V2 USDC 相关市场仅做待上线预留，待市场地址确认后接入。
- 高风险地址来源一期可用人工维护观察名单，后续再评估内部或第三方安全标签源。

## 依赖与风险

| 项目 | 描述 | 影响 | 缓解措施 |
|------|------|------|---------|
| watched address 口径 | 市场合约、reserve、bot、admin 等地址未最终确认 | 影响扫描覆盖范围 | PRD 中标记待确认，评审时明确地址配置来源 |
| USDCOLD 合约能力 | 暂未确认是否支持 freeze / blacklist / pause | 影响冻结状态判断 | 先展示能力待确认，确认后补充状态检查 |
| 黑名单状态查询 | 依赖 USDT 合约状态查询 | 状态查询失败会影响当日结果 | 增加失败状态和重试机制 |
| 高风险地址来源 | MVP 依赖人工观察名单 | 风险资金识别覆盖有限 | 一期先做配置化，二期评估安全标签源 |
| 估值依赖 | 依赖价格源和 exchangeRate | 影响高风险流入阈值判断 | 价格缺失进入待估值，不直接降级 |
